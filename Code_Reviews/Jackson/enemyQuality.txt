quality comments

* Both enemy manager and enemy creator work well and are separated neatly.
  Creator handles the creation of enemies and all their attributes, while
  manager handles updating, drawing, and respawning them.

* While the manager has no major issues in my opinion, the creator suffers
  from a somewhat bloated switch statement that could cause problems when
  adding new enemies. This includes a lot of repeated code. I know there are
  plans to change this though, so it is not the biggest issue. For example,
  the currently duplicated textures will eventually be changed to different
  ones for each enemy.

* The GetSpawnBehavior method is set up well for future changes. If each
  enemy were given its own spawning behavior, it could be added to the switch
  without needing to modify enemy manager.

A hypothetical change would be to give each enemy its own spawning behavior.
This should be easy to accomplish because the method already has a switch
prepared for this without needing to modify enemy manager. This would further
bloat the switches though and make them harder to maintain if more enemy
types are added.

I think both files have good separation and work well together. The
main issue is the switch statement in enemy creator, but I don't think it is
a major problem.
